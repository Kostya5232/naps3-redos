# NAPS3 для РЕД ОС и Windows

GTK-приложение для сканирования документов через USB и сеть. Поддерживает
стекло, автоподатчик, ручной и аппаратный дуплекс, импорт страниц и сохранение
в PDF, TIFF, PNG, JPEG, BMP и WebP.

Текущая версия — **0.9.7** для **РЕД ОС 8 x86_64** и **Windows 10/11 x64**. В выпуск также входит предварительный 32-битный пакет для **Windows 7 x86/x64**.
Интерфейс, работа со страницами и защищённое сохранение общие для обеих ОС.
В РЕД ОС используются SANE/eSCL, в Windows — установленный системный драйвер WIA или TWAIN.

## Windows

Скачайте установщик из последнего выпуска и запустите его:

- [NAPS3-latest-Windows-x64.exe](https://github.com/Kostya5232/naps3-redos/releases/latest/download/NAPS3-latest-Windows-x64.exe)
- [NAPS3-latest-Windows-x86.exe](https://github.com/Kostya5232/naps3-redos/releases/latest/download/NAPS3-latest-Windows-x86.exe) — предварительный установщик для Windows 7 x86 и x64
- [все файлы выпуска и контрольные суммы](https://github.com/Kostya5232/naps3-redos/releases/latest)

Установка выполняется для текущего пользователя и не требует покупки лицензии
или отдельной подписки. Если сканер не появляется в списке, установите WIA-драйвер
производителя МФУ. Для переносного запуска в выпуске также есть ZIP-архив.

Windows-версия не запускает PowerShell-скрипты: доступ к системному WIA выполнен
через поставляемый `NAPS3.WiaBridge.exe`. Ранние ошибки запуска записываются в
`%LOCALAPPDATA%\NAPS3\startup.log`; ярлык журнала находится в меню «Пуск».

Windows-пакет пока не подписан коммерческим сертификатом, поэтому SmartScreen
может показать стандартное предупреждение для нового издателя. SHA-256 каждого
файла публикуется рядом с установщиком.

## РЕД ОС: установка одной командой

Прямо из выпуска GitHub:

```bash
sudo dnf install -y https://github.com/Kostya5232/naps3-redos/releases/latest/download/naps3-latest.x86_64.rpm
```

Чтобы получать следующие версии обычной командой `dnf upgrade`, один раз
подключите бесплатный репозиторий:

```bash
sudo curl -fsSL https://kostya5232.github.io/naps3-redos/naps3.repo -o /etc/yum.repos.d/naps3.repo && sudo dnf --refresh install -y naps3
```

После этого обновление выполняется вместе с системой:

```bash
sudo dnf --refresh upgrade -y naps3
```

Репозиторий пока публикуется без RPM-подписи (`gpgcheck=0`). Пакеты и метаданные
передаются по HTTPS, а GitHub Release дополнительно содержит SHA-256.

## Что изменилось в 0.9.7

- В РЕД ОС при подключении Kyocera ECOSYS MA4000x по USB NAPS3 предлагает скачать официальный SANE-драйвер после согласия пользователя.
- Загруженный архив проверяется по SHA-256; нужные файлы размещаются в профиле пользователя без запуска установочных скриптов Kyocera.
- Правило USB-доступа ограничено устройством `0482:0de0`. Драйвер Kyocera не входит в пакет NAPS3 из-за условий его лицензии.
- В выпуск включены изменения 0.9.6 для Windows, включая предварительный пакет Windows 7 x86/x64.

## Подготовлено в 0.9.6

- Подготовлен один 32-битный пакет для Windows 7 x86 и x64 с Python 3.8 и GTK 3;
- импорт PDF в этом пакете работает через PDFium, остальные сборки сохраняют `pdftoppm`;
- WIA/TWAIN-помощники работают без PowerShell-скриптов; установщик проверяет наличие KB2533623;
- в Windows можно выбрать поиск WIA, TWAIN или обоих способов; TWAIN читает аппаратные возможности АПД и предлагает двустороннее сканирование, когда его сообщает драйвер;
- TWAIN включает автоподачу при поддержке драйвером, ждёт первую страницу АПД до 90 секунд и сокращает ожидание закрытия одностраничного скана со стекла;
- для сканирования через WIA/TWAIN нужен .NET Framework 4 и драйвер устройства;
- фактическую скорость и аппаратный дуплекс Kyocera, а также совместимость на двух Windows 7 ещё нужно проверить на МФУ.

## Что изменилось в 0.9.5

- Добавлено отдельное TWAIN-подключение для Windows, если WIA-драйвер возвращает ошибку;
- на Kyocera ECOSYS MA4000x по USB проверены стекло и автоподатчик через TWAIN;
- TWAIN-сканирование изолировано в 32-битном процессе и ограничено по времени и числу страниц.

## Что изменилось в 0.9.4

- Исправлен сбой Windows-сборки 0.9.3 до появления окна: в пакет включается
  проверенная DLL Cairo 1.18.4-4 с контролем SHA-256;
- сборка теперь проверяет, что настоящее окно NAPS3 появляется и приложение
  остаётся работающим после запуска;
- сканирование Kyocera ECOSYS MA4000x по USB в Windows пока не подтверждено:
  официальный WIA-драйвер на проверенном ПК видит МФУ, но отвечает ошибкой
  `0x80210001` при подключении. Исправление запуска не устраняет этот сбой.

## Что изменилось в 0.9.3

- Windows WIA теперь выбирает элемент стекла или автоподатчика по правильной
  категории драйвера. Это устраняет попытку сканировать со стекла через первый
  элемент МФУ, который мог оказаться автоподатчиком;
- если фильтр поиска указывает Kyocera, а рабочим остаётся сохранённый HP,
  программа предупреждает об этом до начала сканирования;
- общая ошибка WIA `0x80210001` один раз повторяется на том же устройстве;
  диагностическое сообщение показывает этап сбоя.

Фильтр поиска не переключает рабочее устройство сам. После ввода названия
нажмите «Подключить сканер…» и выберите нужное МФУ. Если Kyocera отсутствует в
списке WIA, проверьте его подключение и установите WIA-драйвер производителя.

## Что изменилось в 0.9.2

- PowerShell удалён из цепочки запуска и сканирования Windows WIA;
- системный WIA вызывается через небольшой скомпилированный помощник;
- политика запрета PowerShell-скриптов больше не мешает открыть NAPS3;
- ошибки до появления окна сохраняются в `startup.log` и показываются отдельным
  системным сообщением.

## Что изменилось в 0.9.1

- Windows теперь ищет сетевые eSCL-сканеры через DNS-SD/mDNS по всем активным
  IPv4-интерфейсам;
- найденные устройства проверяются по `ScannerCapabilities` и появляются в
  списке выбора вместе с IP-адресом;
- диалог явно сообщает, завершился ли поиск с результатами; ручной ввод IP
  остаётся доступным.

## Что изменилось в 0.9.0

- Printer Doctor может передать в NAPS3 выбранный и уже проверенный сканер;
- официальный CLI принимает точный SANE ID или адрес eSCL и повторно проверяет
  только это устройство;
- профиль сохраняется атомарно с резервной копией, остальные настройки остаются;
- регистрация от `root` запрещена, а открытое окно NAPS3 блокирует внешнее
  изменение профиля.

```bash
naps3 --register-scanner --device-id 'pixma:04A92737_1M66352840' --name 'Canon MF4410'
naps3 --register-scanner --device-id 'airscan:e0:Office' --connection network --name 'Office'
naps3 --register-scanner --address 192.168.1.50 --name 'Сетевой МФУ'
```

Для машинного вызова доступен `--json`, версия интерфейса выводится командой
`naps3 --registration-api-version`.

## Что изменилось в 0.8.4

- при запуске проверка сохранённого сканера блокирует кнопку сканирования до
  освобождения SANE-backend;
- повторный поиск устройства также не может пересечься с началом сканирования;
- краткий ответ `Device busy` вызывает один повтор через секунду на том же
  выбранном USB-сканере;
- повтор не запускает общий поиск и не может переключиться на другое МФУ.

## Что изменилось в 0.8.3

- сканирование со стекла через SANE получает универсальный PNM и проверяет
  завершение `scanimage` до создания страницы;
- полученное изображение полностью декодируется и атомарно преобразуется в PNG;
- оборванная страница не добавляется в проект и не вызывает лавину окон GTK;
- служебный вывод SANE ограничен последними строками, а интерфейс обновляется
  только при реальном прогрессе;
- одно пакетное задание ограничено 200 страницами, а обработка 600 dpi выполняется
  последовательно для защиты памяти;
- USB-диагностика теперь объясняет нехватку прав и отсутствие backend для
  сканеров любых производителей.

## Что изменилось в 0.8.2

- исправлены права Canon MF4410 в удалённых графических сессиях;
- позднее udev-правило выдаёт доступ только USB-устройству `04a9:2737`;
- установщик сразу применяет права к уже подключённому Canon;
- backend `pixma` проверяется отдельно, даже если отсутствует в `dll.conf`;
- RPM обязательно устанавливает пакет аппаратных SANE-драйверов.

## Что изменилось в 0.8.1

## Проверка и сборка

Linux:

```bash
python3 -m unittest discover -s tests -p 'test_*.py'
./build_rpm.sh
```

Windows 10/11 x64 собирается в окружении MSYS2 UCRT64:

```bash
./windows/build_windows.sh
powershell.exe -File windows/build_installer.ps1
```

Кандидат Windows 7 x86/x64 собирается в GitHub Actions через
[отдельный сценарий](.github/workflows/windows7-x86-prototype.yml) на Python 3.8 x86.

Теги вида `v0.9.7` запускают GitHub Actions: тесты, сборку RPM, двух Windows-пакетов,
создание общего выпуска и обновление DNF-репозитория на GitHub Pages.
